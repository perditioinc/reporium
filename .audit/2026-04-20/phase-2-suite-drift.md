### Fields in API `RepoSummary` NOT in TS `EnrichedRepo`:
| API field | Notes |
|---|---|
| `id: UUID` | TS uses numeric id — this is a real type mismatch |
| `ingested_at: datetime` | Not exposed to TS consumers |
| `updated_at: datetime` | Not in EnrichedRepo |
| `problem_solved: str` | In API, not in EnrichedRepo |
| `allCategories: list[str]` | Present in RepoSummary but not directly on EnrichedRepo (it has primaryCategory + allCategories) |

### Summary of Contract Drift:
The TS `EnrichedRepo` type is built primarily from the **library.json static file** (generated by the ingestion pipeline), NOT directly from the API's `RepoSummary` schema. The API's `RepoSummary` is used by the nightly sync endpoint. These two representations have significant naming divergence (snake_case vs camelCase throughout) and structural differences (nested computed fields in TS that don't exist in API). The `id` type mismatch (UUID vs number) is the highest-risk discrepancy if both code paths are ever used interchangeably.

## Limitations

1. **Dead code scan is approximate**: The TS scan uses basename matching against import strings — dynamic imports (e.g. `React.lazy`, `next/dynamic`) and string-based routing won't be detected. Some flagged "unreferenced" components are likely dynamically imported. Python scan found no unreferenced modules in reporium-api because all are reachable via FastAPI router registration, which uses import side effects.

2. **OpenAPI spec**: No static openapi.yaml exists in reporium-api. The spec is served dynamically by FastAPI at `/openapi.json` at runtime — there is no committed spec file to audit for staleness.

3. **CI failure root cause depth**: Failure logs were retrieved for the 3 failing repos. Root causes identified (expired GH_TOKEN, Cloud SQL proxy timing, missing GCP auth secret) but not confirmed by inspecting secret states (requires GCP/GitHub admin access).

4. **Contract drift analysis**: Comparison was done between the ORM model (`app/models/repo.py`), API output schema (`app/schemas/repo.py::RepoSummary`), and TS types (`src/types/repo.ts::EnrichedRepo`). The actual API-to-frontend data path uses library.json (a static JSON file generated by ingestion, not a live API call for most pages), so some apparent drift is intentional — the TS type describes the library.json shape, not the API's REST shape directly.

5. **Repos not on disk**: All 15 repos were found on disk at `C:\DEV\PERDITIO_PLATFORM\` — no cloning was required.

6. **Wall clock time**: Audit completed within budget (approx. 15 minutes).
